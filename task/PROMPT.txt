实现已归档软件包的离线存档审查，输入只含合成的制品摘要与签名有效布尔标记。每份签名附发行者、签名者和未知签署时刻的闭整数区间；多个可信时间见证分别约束同一个签署时刻，取交集。签名审核要求签署时刻落在签名者获授权区间内、其授权链可达可信根、每条链路当时有效且未被列入历史撤回区间。记录分为生效时间和录入提交号，后录入的修订能在更新视图追溯撤回，同时保留以前的 as_known 查询。授权链可在不同时间段换路，不要求一条链贯穿全部时间；度数较高的图允许环，见证只给简单路径。
inspect 把所有候选签署时刻精确划分为可确证通过、拒绝及缺少证据三类：有可信时间见证且存在有效路径的时刻通过，观察到确凿签名无效或全部候选链均被明确撤回的时刻拒绝，其余为缺少证据。候选链指忽略撤回、仍满足根、方向及当时各边生效条件的路径，空链集属于缺少证据。输出各段端点、字典序最小的最短通过路径或缺失／拒绝原因，合并结果和证据完全相同的相邻段。完整签署区间都通过才能登记 approved；任一时刻拒绝则 rejected，其余 uncertain。输入为非负秒，最长跨度十年，不能逐秒枚举。测试覆盖交叠见证冲突（显式 invalid_evidence）、闭区间单点、两个路径相接覆盖、迟到修订及同一制品的前后录入视图。

通过条件还必须获得独立时间见证。可以有多份签署时刻的候选时间记录，每份有自己的区间、来源组织和通向可信根的认证路径。独立门槛为输入整数 q（1 到 3），同一时刻选出的 q 条见证路径与制品签名路径合计必须有不同来源组织、非根节点互不相交。共享根允许。只有被标记为必采的时间约束直接交集；其他时间记录是该时刻可参加的候选见证，未选者不收窄签署区间。原先“有可信时间见证”改为至少 q 条满足独立性的见证，判定要同时搜索制品签名路径和全部见证路径。通过时取总边数最小、再按签名路径和依见证 ID 排序的见证路径序列字典序最小的组合；独立性不足且存在未撤回的签名路径时归为证据不足，并给最大可达到的独立见证数。补充要求 crosscheck 对前后两个录入视图找最小改变的时间段和证据来源。测试必须证明选择最短的制品签名路径可能阻塞所有可信时间见证、两条看似来自不同机构的路径共享同一中间节点、补录只撤回一个中间节点影响多个证明，以及空区间与单点区间。使用小有向图和明确的录入事件进行独立对照。

使用 Windows 原生 Python 3.12、标准库和 CPU，从空仓库实现，所有夹具用本地虚构数据。命令格式为 python -m solution <命令> CASE.json，涉及持久状态的命令带 --db DB.sqlite。标准输出为 UTF-8 JSON，同一逻辑输入产生同一结果；结构错误给出可定位的错误码及字段位置。交付可直接运行的样例、README（含完整输入输出定义与复现命令）和可用 python -m unittest discover -s tests -v 执行的断言测试。
